# Final resilience matrix

This directory is the index for the production failure-injection gate. The
small contract suite here makes safe degraded outcomes directly visible. The
linked integration and browser tests exercise the same controls at their real
database, storage, and user-interface boundaries.

| Scenario                       | Injected failure/race                                                                    | Required safe outcome                                                                | Executable evidence                                                                                                                                |
| ------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unique last item               | Two checkouts reserve the same final unit concurrently                                   | Exactly one reservation succeeds; the other receives a safe stock conflict           | `tests/integration/checkout/concurrency.test.ts`                                                                                                   |
| Payment uncertainty and replay | Repeat create/refund keys and force an uncertain provider state                          | References remain stable; uncertain is never treated as paid; refunds are idempotent | `tests/resilience/failure-matrix.test.ts`, `tests/contract/payments/payment-provider.test.ts`                                                      |
| Refund and restock replay      | Repeat refund and restock commands                                                       | Money and inventory effects apply once                                               | `tests/integration/returns/return-workflow.test.ts`                                                                                                |
| Upload interruption            | Remove an uploaded original, expire the worker, leave corrupt partial output, then retry | Job becomes safely retryable and produces one clean rendition set                    | `tests/resilience/failure-matrix.test.ts`, `tests/integration/ingestion/media-pipeline.test.ts`, `tests/e2e/product-ingestion-recovery.spec.ts`    |
| Queue lease contention         | Competing worker claims an already leased action                                         | Only the lease holder can heartbeat/complete it                                      | `tests/integration/operations/production-operations.test.ts`                                                                                       |
| Notification failure           | Email provider is disabled or unavailable                                                | Notification remains unsent/retryable and no false delivery is shown                 | `tests/resilience/failure-matrix.test.ts`, `tests/contract/payments/email-provider.test.ts`                                                        |
| Missed schedule                | Coordinator starts after multiple missed intervals                                       | Catch-up is oldest-first, bounded, and idempotently enqueued                         | `tests/resilience/failure-matrix.test.ts`, `tests/unit/operations/scheduler.test.ts`, `tests/integration/operations/production-operations.test.ts` |
| Provider outage                | Payment/email integration is disabled or times out                                       | Operation fails closed with a safe, typed availability result                        | `tests/resilience/failure-matrix.test.ts`, `tests/unit/operations/external-degradation.test.ts`, provider contract tests                           |
| Export failure                 | Export worker fails after taking a lease                                                 | Job records a safe code, ends in failed state, and releases its lease                | `tests/resilience/failure-matrix.test.ts`, `features/catalog/exporter.ts`                                                                          |
| Session revocation             | A revoked staff/customer session reaches a command boundary                              | Authorization fails before protected work runs                                       | `tests/resilience/failure-matrix.test.ts`, `tests/integration/auth/authorization.test.ts`, `tests/integration/customer/customer-account.test.ts`   |

Every row is mandatory. A skipped database or browser test is not release
evidence; the final run must use the local Supabase stack and local application
server so those suites execute rather than skip.
